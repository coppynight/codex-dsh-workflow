# DSH 主控探索：便宜路径已经成立，专家升级尚未证明

2026-09-09。**值得继续做一个小而可验证的产品；还不值得宣传“通用 90% 能力、十分之一价格”。**
本轮交付了真实模型实验、可运行核心、一个组合 CLI 入口和公开回放材料。
[产品判断与下一步](DECISION.md) · [原型使用](../../prototype/README.md) · [页面](https://coppynight.github.io/codex-dsh-workflow/)

## 测到了什么

22 次任务尝试，涉及 4 个不同任务。前三题完成原生 Astra、DSH 独立执行、DSH + 可选 Astra
三臂对照；后续是在同样题目上的配置探索。第四题仅启动 Astra，遇到费用证据不完整后停止。
**22 次尝试不是 22 个独立样本，只有 3 个任务有完整模型对照。**

| 配置（前三个同题任务） | 产物通过 | 自主交付 | API 等价费合计 | / Astra 费用 | / Astra 耗时 | 专家咨询 |
|---|---:|---:|---:|---:|---:|---:|
| 原生 Astra / medium | 3/3 | 3/3 | $1.205198 | 100% | 1.00× | — |
| Flash / high 独立执行 | 3/3 | 2/3 | $0.177225 | 14.7% | 2.04× | 0 |
| Flash / high + 可选顾问 | 3/3 | 3/3 | $0.159817 | 13.3% | 1.94× | 0 |
| Flash / low 独立执行 | 1/3 | 0/3 | $0.064376 | 5.3% | 0.66× | 0 |
| Flash / low + 可选顾问 | 2/3 | 1/3 | $0.075999 | 6.3% | 0.79× | 0 |
| low + 兼容自测命令 + 可选顾问 | 2/3 | 1/3 | $0.083793 | 7.0% | 0.87× | 0 |
| low + 独立验收 + 一次 high 修复 | 2/3 | 2/3 | $0.210413 | 17.5% | 2.01× | 0 |

最后一行首次验收通过 1/3；两次修复计入全部费用。不同配置未做足够重复，顺序、缓存与
服务负载也会影响结果；不能把两个 high 臂的差值解释成顾问的收益，因为都没有调用顾问。
耗时是控制器执行阶段，反馈阶段包含验收；Host 启动另外记录，不属于上述比值。

“自主交付”要求产物通过、运行正常完成、写入任务树已空闲、可见测试未改、咨询协议有效。
产物通过但停下来请求权限、最终状态解析失败，都不算自主交付。实验过程中有基础设施修正，
没有人工修改任何参测模型的任务代码。**运行内无人改代码，不等于产品已经零维护。**

## 四个值得保留的发现

1. **高强度的廉价模型比预想更接近目标。** 三个明确规格的小组件都生成了合格产物，
   峰时等价费为 Astra 的约 13–15%。这是模型价差和便宜执行路径的证据；不是专家路由收益。
   代价是约两倍等待时间，样本也不足以说明更复杂仓库的表现。
2. **最低单次价格不等于最低交付成本。** low 出现 `constructor` 等对象键、整数边界、
   终态幂等问题；其中一项通过一次修复，另一项修复后仍失败。高质量验收与选择升级的时机
   比统一降低思考强度更重要。当前默认保留 high，low 只作为显式实验选项。
3. **“能问专家”不会自动变成“会在正确时机问专家”。** 所有任务中的咨询次数是 0。
   单独 MCP 探针确实完成一次 Astra 咨询，同 ID 重放使用缓存，超过次数被拒绝；这证明接入
   可行，不能证明 DSH 自主升级、专家建议增益或更低成本。[探针记录](probes.json)。
4. **无人值守也需要可靠地停下。** 第四题 Astra 正常退出前有多次连接超时，只有终局部分
   用量，完整重试成本未知。程序阻止后续付费，未进行预定修复，也未启动两个 DSH 对照或
   已准备的 Pro 尝试。随后只读验收 7/8；并发读写检查观察到 worker 的 `EPERM`，可能与
   Windows 文件替换时的共享占用有关，但没有据此更改模型产物。此题没有模型优劣结论。

## 费用口径

[summary.json](summary.json) 保存逐次用量、费率、覆盖证据、修复、耗时和汇总。
所有已提交实验及两个探针可观察到的 API 等价费为 **$2.813363**，其中 DeepSeek 峰时等价费
**$0.771623**。该总额含第四题已观察到的 **$0.624950**；第四题完整费用仍为 `null`，
因此不能把 $2.813363 称作最终完整账单。父级研究、选题、原型开发和审查费用未分摊。

| 冻结费率，美元 / 百万 token | 未缓存输入 | 缓存读取 | 输出 |
|---|---:|---:|---:|
| Astra 标准 API 等价 | 10 | 1 | 50 |
| DeepSeek V4 Flash 峰时 | 0.44 | 0.014 | 1.32 |
| DeepSeek V4 Pro 峰时（未实测） | 1.32 | 0.044 | 3.96 |

来源及计量说明见 [SOURCES.md](SOURCES.md)。当前 DeepSeek 公布的非峰时价格为峰时一半；
本报告统一使用峰时以便保守比较。非峰时情景会使无专家 DSH 费用比例减半，但**不能把
这个换算写成路由效率提升，也没有用它倒推出套餐倍率**。Astra CLI 请求精确型号，实际路由
未出现在事件流中；超长上下文请求分档和不完整重试不能可靠还原时保留未知。

## 样本和方法边界

- `incremental-observation`：在仓库历史提交 `5e4bc6e` 的真实摘要模块上实现新增接口要求。
- `usage-ledger`：新用量账本，覆盖累计/增量、缓存、重放、缺失费率、异常键和原子性。
- `budget-reservations`：新费用预留状态机，覆盖幂等、超支、未知提交、终态和安全整数。
- `durable-jobs`：调优后另行冻结的磁盘持久化与跨进程并发任务；未完成三臂对照。

都属于小组件或局部集成，不能代表完整应用交付。初始三臂没有向模型反馈隐藏验收；后续
反馈阶段最多返回一次失败输出，所以是反馈辅助策略，不是盲测。便宜侧保留 DSH 标准工具，
Astra 用原生 Codex 普通文件/shell/测试工具；不绕过沙箱审批。适合的 Node 自测改用
`--test-isolation=none`，外层沙箱保持不变。需进程隔离的测试不能一概这样替换。

原验收有一处越界断言，修正后重验同一 Astra 产物，没有重跑模型；旧断言与旧结果在根目录
保留。预算题语义澄清发生在该题任何调用前。第四题的争用时限澄清发生在首次调用前，旧
freeze 和旧验收保留。初始 native 记录尚无显式 cleanup 字段，以正常退出记录为依据并单列
披露。早期每次运行没有记录所有运行器文件哈希，工程演进见 Git 历史与
[研究协议](../../experiments/dsh-led/PROTOCOL.md)。

## 不调用模型的回放

```text
node examples/dsh-led-v5/replay.mjs
```

需要 Node 24，无模型、密钥或 DSH。逐一检查产物及验收 SHA-256，再比较每项测试的名称和
通过/失败结果；启动失败、超时、验收未完整执行不能算复现成功。Windows 本机此次 22/22
记录一致，包含原本失败的检查。第四题涉及 Windows 并发行为，其他平台或另一次调度可能
不复现该失败；应报告差异，不能把不同的错误当成同一失败。

每个阶段保留 freeze，每个尝试保留任务、提示、最终源代码、哈希、验收输出和计量。
原始推理、密钥、账号标识与私有运行路径不公开。`pilot-pro-01` 只有未执行的计划，
不能计入模型成绩。完整评估与产品建议见 [DECISION.md](DECISION.md)。
