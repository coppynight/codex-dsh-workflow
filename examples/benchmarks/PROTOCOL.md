# 预先约定的试验口径 · 2026-09-08

这是两项小规模、本机、单次配对案例，不是通用能力排行榜。预先选择日志脱敏（纯函数）与 checkpoint 存储（文件集成及错误分支）：代表可委派的边界明确工作，同时保留小任务可能不值得委派的反例。

两条路径使用同一份需求、初始文件、可见自测和预先冻结的独立验收断言。独立断言只覆盖明确需求；首次模型执行前已写入 cases.mjs，对执行者不提供该文件位置和内容。起始 solution.mjs 为空，禁止越出任务目录找答案。

- A：固定请求 `gpt-6-astra`、medium，用一次 Codex CLI 会话实现并自测。
- B：配置的 DSH 实现并自测，然后相同 `gpt-6-astra`、medium 在独立会话检查、必要时修复并复验。
- 两条路径最终由同一个独立验收程序判定。每个模型阶段最多 10 分钟，一轮执行，无静默重跑；失败和全部实际用量保留。
- 第一案例先 A 后 B，第二案例先 B 后 A。每条路径使用独立空目录，无彼此的源码、输出和缓存目录。
- 统计边界：固定需求后的**受控执行子会话**；不含本次页面开发、实验设计、主会话协调与公开材料编写消耗。不得据此声称完整项目端到端 token 节省。
- Codex JSONL 的 `turn.completed.usage` 是用量来源：input（包含缓存部分）+ output = measured total；cached_input 单列，不再相加。保留原始 usage 对象，模型字段记录 requested，不伪造服务端模型证明。
- DSH 用量仅在官方会话事件可获取时记录；否则为 null/未取得。绝不把缺失记成 0。不声明总 token、总账单或订阅额度节省。
- 两例全部披露，包含零收益、负收益、失败与 wall time。案例不是统计显著结论，也不能推断模型整体优劣。

优化触发：B 未通过相同验收或 Astra 用量没有下降。保留原始运行结果，明确改变的规则；若需要比较新流程，重新运行双方并另存 revision，不用新结果覆盖旧结果。已有具体验证支持的非模型改进（例如重复轮询响应精简）可独立测量传输量，不能混称实测 Astra token。

## Revision 2：只读策略下的代码生成对照（运行前修订）

首轮 A（log-redaction-astra）被本机子 CLI 的执行策略拒绝，未产出实现；完整 usage 单列为环境失败，不混入有效配对均值。没有放宽策略或重复被拒操作。首版验收生成器另发现换行转义错误，已在有效试验前用 node --check 修正；未根据模型答案修改断言。

后续统一使用 r2 新目录，Astra 两个路径都保持 read-only、禁用工具，只把完整需求、可见测试和（B 路径）DSH 源码作为输入，以固定 JSON schema 返回完整代码。父级确定性 harness 写入返回源码并执行同一独立验收。DSH 仍实现并自测；Astra 无权声称执行测试。此对照衡量受控代码生成/审查子阶段，不衡量 Astra 自主使用工具的端到端表现。所有其他规格、顺序、单次限制与统计口径保持。Pilot 与 r2 分开保留，不能用 pilot 的失败/用量作为节省分母。

验收勘误（r2 第一例 A 返回后、B 返回前）：最初日志断言还要求 JSON 的 TOKEN 大写键脱敏，但冻结需求仅明确 Bearer 大小写不敏感，JSON 枚举的是 token 等键。该断言超出规格，移出两条路径的主评分（现 12 项），保留 A 的原始 12/13 结果于 results/log-redaction/acceptance-before-spec-correction.json 和修订记录；不据此宣称模型遗漏。只重跑验收，不重跑模型。旧评分记录、被移除的断言（JSON TOKEN 大写键）及发生时点公开，以便审查潜在选择偏差。初版换行语法修复与此项内容勘误不同。
