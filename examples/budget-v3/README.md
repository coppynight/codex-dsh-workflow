# 更低成本使用 Astra，更少人工介入：第三版实验

2026-09-08。**项目价值定位是：Astra 负责规划、思考与验收，低价模型执行，让使用者以更低成本获得完整交付，并减少亲自调度与救场。** 总 token 更少并不是目标。本轮对成本方向得到初步支持；尚未证明人工干预大幅下降，更没有证明 $20 套餐媲美 $100/$200。

## 本轮做了什么

真实运行一个三文件离线 job-report CLI：解析 NDJSON、汇总任务状态与耗时、原子写报表。两边共享一次真实 Astra 规划；A 由 Astra 实现，B 由 DSH / DeepSeek v4 Flash 实现与自测。再用独立 Astra 会话盲审，审查者只返回结论和问题，不重写代码。最后执行预先冻结、此前未提供给执行者的 17 项检查。两边均无需审查修复。

| 指标 | A：Astra 规划、实现、验收 | B：Astra 规划验收 + DeepSeek 执行 |
|---|---:|---:|
| 产物检查 | 17/17 | 17/17 |
| 独立 Astra 审查 | accept | accept |
| Astra API 等价成本 | $0.598380 | $0.372760 |
| DeepSeek 执行成本估算 | $0 | $0.113859 |
| 已记录模型阶段合计 | $0.598380 | $0.486619 |
| 模型阶段总用时 | 128.874 秒 | 579.295 秒 |
| 新增需要用户处理的请求 | 0 | 0 |
| 实际用户处理动作 | 0 | 0 |
| 严格执行契约 | 符合 | 临时目录写入范围有偏差，见下文 |

来源：[分阶段结果](results/summary.json)、[各阶段记录与源码](results/)、[人工介入记录](results/interventions.json)。**Astra 等价成本下降 37.7%，加入 DeepSeek 后已记录模型成本下降 18.7%；时间增加至约 4.50 倍。** 这是产物达到相同测试标准的成本比较，不代表严格遵守全部过程契约的交付率。

## 怎样记账

共享规划 $0.184670 在每条反事实路径各计一次，实际实验只运行一次。A 的实现 $0.242650、验收 $0.171060；B 的 DeepSeek 实现自测 $0.113859184、Astra 验收 $0.188090。实际实验的已记录模型支出等价合计 $0.900329184，不能简单把两臂总价相加而重复计算共享规划。

按截至当日的标准、短上下文价格，每百万 token 的美元权重如下：

| 模型 | 未缓存输入 | 缓存命中输入 | 输出 |
|---|---:|---:|---:|
| Astra | 10 | 1 | 50 |
| DeepSeek v4 Flash 非高峰 | 0.22 | 0.007 | 0.66 |
| DeepSeek v4 Flash 高峰 | 0.44 | 0.014 | 1.32 |

来源：[Astra 官方模型价格](https://developers.openai.com/api/docs/models/gpt-6-astra)、[DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)。本次 DSH 的全部模型事件位于工作日 UTC 06:19–06:28 高峰窗口，按高峰费率计。没有用非高峰价格美化本次结果；历史两例发生在非高峰。

Astra input_tokens 含缓存命中，因此先减 cached_input_tokens；DSH inputTokens 只含未缓存输入，cacheReadTokens 另计。输出已含推理，不能重复相加。DSH 只累计 assistant/message 的 usage，排除 assistant/chunk 的重复份。Astra 非零缓存写入的统计口径未验证，计算器会拒绝，不会猜数。完整价格快照和计算公式见 [pricing.json](pricing.json)、[cost.mjs](cost.mjs)。

这些是 **API 等价成本**，不是 Plus 实际账单或额度扣减。Codex credit 权重重算也只是等价指标。没有读取可归因的个人订阅扣减；主会话设计、委派、观察和整理发布的模型消耗未计价，DSH 辅助标题生成用量不可得。两臂未计开销的差额如果超过约 $0.11176，本例 18.7% 的已记录优势就会被抵消。因此不能把它写成完整端到端节省。

## 人工介入与执行偏差

两条路径都没有新增人工处理请求，**不是人工干预减少 100%**。环境、凭据已在实验前配置；初始化人工成本未知。主控安排任务、应用 Astra 返回的代码、复跑测试、观察 DSH、检查空闲并释放目录，都是自动化工作，但主控模型消耗不在本次计价范围内。

DSH 的 20 次工具调用包含 3 次源文件写入和 17 次 PowerShell 调用。它发现并修正了两处自编测试的预期错误，又花了多轮诊断输出捕获问题。完整事件元数据中没有 approval/asked 或 ask_user_question；两个 user/message 分别为原任务与插件环境上下文，并非用户救场。可核查的脱敏证据见 [execution-audit.json](results/b/execution-audit.json)。执行者自述的额外测试通过数不能当作独立验收，最终结论以外部 17 项检查为准。

**过程偏差保留：** DSH 自述在系统临时目录创建并清理了自测文件，原任务包却只明确允许写三份源文件。最终目录只有三份源文件和未修改的可见测试，产物通过验收；这仍不算严格过程契约合规。已更新 skill 任务模板，要求明确自测临时目录范围，避免“需要自测但没有允许测试临时文件”的含混契约。没有事后修改本轮任务包来抹去偏差。

六项离线故障夹具重新执行均通过，包括有界启动、认证刷新、陌生端口保护、进程未就绪、缺凭据引导和 checkpoint 保留。[测试与结果](recovery-results.json)。它们证明对应恢复/停止分支有效，不证明六次真实交付成功，也不是原生 Codex 与工作流的人力 A/B。

## 对 skill 价值的判断

**方向匹配，收益取决于任务结构。** 本次把实现从 Astra 转出，使 Astra 等价成本下降 37.7%；廉价执行者即使有大量额外推理和自测，计价后仍可能便宜。但高峰 DeepSeek 的费用与更长耗时吃掉了部分收益。成本、时间、人工请求要分开看。

本例基线的规划与验收占 Astra 成本约 59.4%。即使实现完全免费、没有新增协调，这种阶段结构的理论容量上限也只有约 1.68 倍；实际测得 Astra 加权成本比约 1.61 倍，**不是实测套餐容量比**。要达到 5/10/20 倍，需要任务里 80%/90%/95% 的 Astra 净消耗可被转出，且质量、额度线性、限速和耗时条件同时成立。这要求更高比例的执行工作、更少重复审查和更低的主控协调开销，不能靠宣传数字实现。

截至当日，[官方套餐](https://learn.chatgpt.com/docs/pricing)列出 Plus $20、Pro $100 对应 5 倍用量、$200 对应 20 倍。套餐价格比不是额度比；Plus 加 DSH 的实际支出也不再只是 $20。现阶段不能发布“一个账号顶十个账号”。

**减少人工介入的机制已具备，幅度尚无数据支持。** 原生 Codex 本身可自主实施、测试和恢复。要证明 skill 的额外价值，应以相同原始工具但不加载 skill 为另一对照，记录真正需要人处理的事件、阻塞时间、最终通过率以及冷启动成本。健康运行双方零介入，无法证明差异。

## 已落实的优化与下一轮判据

已将以下行为写入实际安装的 skill：把可共同验收的实现合为任务包；审查返回具体问题、原执行者修复；重复失败或两轮修复不收敛时停止反复委派；已有授权内诊断、恢复和降级由 Codex 处理；区分自动动作与必须用户处理的事件；明确自测临时目录边界。它们是新规则，不将本次结果冒充所有规则优化后的复验。

下一轮应交错重复「原生 Astra」「同样原始工具、无 skill」「完整 skill」三臂，在正常工具权限下覆盖执行占比高的跨文件改造和预登记故障；事先冻结需求、预算、超时、验收和人工事件定义。完整记录父级主控与失败/接管成本，测真实任务吞吐。若规划验收占比过高，直接做；若依赖维护吃掉节省，就减少依赖；若人工请求没有下降，就优化具体阻塞来源。成本低且少救场才是目标，模型越多不代表越好。
