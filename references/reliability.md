# 故障恢复与长任务续作

先读返回 JSON 和退出码，不把后台可连、模型可用、任务完成混为一谈。恢复入口只恢复观察/服务，不会委派、续作、取消或释放任务。

```text
node scripts/dsh-recover.mjs
node scripts/dsh-recover.mjs --task-id 原来的taskId
```

每次通过新的 bridge 子进程检查认证状态，避免长驻 MCP 的缓存；使用相同配置和 stateDir。读写任务状态丢失时不新建替代 ID。CLI 替代 MCP 不改变幂等记录。

## 故障决策

| 观察 | 处理与边界 |
|---|---|
| Node/桥接依赖/DSH 缺失 | `doctor` 给安装路径；完成已授权的本地配置，真实模型验证标为待完成，Codex 继续 |
| Host 连通但 key 缺失、401/403、provider/model 不可用 | 在 DSH 设置→模型引导使用者配置自己的 key/账号；不重启健康服务，不把 provider 失败算作服务恢复成功 |
| 无监听且无匹配 Host 进程 | 配置 autoStart 后，在启动互斥与二次检查下启动一次，等待认证就绪 |
| 进程仍在初始化 | 有界退避观察，不启动第二份 Host；模型沉默不是故障证据 |
| 其他进程占端口或无法确认身份 | 保留 PID/错误分类，不杀进程、不偷换端口；Windows 能精确识别匹配进程，POSIX 未能认证的监听者保守按未知处理 |
| Host 存在但一直不健康 | 新桥接进程复查；不杀仍可能写入的 Host。原任务状态未知时保留 claim，只在隔离目录继续 |
| delegate/followup 超时或连接断开 | 先读持久记录、原始包和 requestId，恢复观察后查同一任务；不可自动重发或换 ID |
| 任务记录/history 不可读而 Host 正常 | 保留记录与最近成功 checkpoint，不重启 Host，不谎称空闲 |
| 模型中断/报错 | 检查 diff、当前 turn、queue/jobs、本地进程；确认无写入后以新 operationId 对原 task 发有界修复 |
| 队列/问题/审批待办 | 展示真实 DSH Web 操作，保留 checkpoint；不自动回答或批准，不当作崩溃重启 |
| EPERM/测试子进程权限受限 | 记录真实阻塞命令，由主 Codex 在已有权限下执行对应检查；不反复申请更大权限 |
| 磁盘满、配置/持久状态损坏、目录无权限 | 保留原文件；报告确切修复位置。不清空状态、删除锁或选择新 stateDir 绕过问题 |
| Claude 条件不满足、超时或失败 | 保留 incomplete 证据，独立 Codex 审查；无独立上下文则报告自查的局限 |

旧 writer 仍可能活动时，“Codex 兜底”只授权在**另一个隔离目录**写入，或在原目录只读；不能由两个执行者同时写一个目录。文件复制不代表分支状态可安全合并。先确认原任务结束、队列与 jobs 空、有关进程不再写入，再检查和整合差异。

## 有界恢复

单次恢复最多尝试启动一次；探测/进程观察有 35 秒期限，退避 2/5/10 秒。调用期间主 Codex 应分段等待并保持沟通，不重复发起并行恢复。连续三次服务恢复失败进入五分钟冷却；健康的只读 probe 可提前关闭熔断。不要通过换 stateDir 绕过冷却。task/history 错误不累计为 Host 失败。

退出码：`0` Host 健康（有 taskId 时也读取了任务）；`1` 不可用；`2` 冲突/忙；`3` 冷却；`4` Host 正常但任务读取失败；`5` 参数错误；`6` 内部/状态错误。查看 `host`、`task`、`reason`、`attempts` 和 `circuit`，再确定下一步。

恢复记录原子写入，损坏文件不被重置。恢复锁只在原 owner 被证明死亡时，在串行回收保护下处理；bridge 的任务锁和 workspace claim 不由恢复器删除。另一个主机的锁不能夺取。

Windows 启动互斥按当前系统会话和端口区分；POSIX 使用当前用户和端口的排他启动锁。不同用户/会话共用同一个 Host 不在互斥保证内，不并行配置管理同一端口。POSIX 启动锁或 recovery reclaim token 遗留时，先证明相关调用进程已停止，备份事件信息，再仅处理那个命名锁；禁止递归清理状态目录来“恢复”。

启动超时可能已经启动成功；随后只读观察，不能立即再次启动。脚本不会为了恢复而停止现有 Host。必须重启时，由 Codex 先证明所有关联任务空闲并且目标进程身份明确，保存状态后按用户授权做定向操作；无法证明则保留阻塞状态和隔离兜底。

## Checkpoint 与恢复入口

在写入者目录以外或被 Git 忽略的 `.workflow/` 中保存本地 `WORKFLOW-STATE.md`，原始任务包另存不可变文件。记录：用户原始需求与验收条件；cwd/分支/基线；当前写入者；taskId/sessionId/requestId/各 operationId；真实工具状态和时间；实际测试及输出位置；审查者、结果与限制；失败类别/冷却期限/下一步。

更新时用临时文件加 rename，保留上一份有意义状态。委派前、阶段完成后、上下文交接前及有实际进展时至少每五分钟更新。无变化不反复重写日志。上下文丢失、应用重开、手工继续时：先读取 checkpoint、检查 Git 状态、恢复观察、查询原请求，再继续下一里程碑。

长时间没有事件先查看 Host/task/队列，不直接取消。若两次相隔五分钟的状态与证据均不变，再调查具体工具或模型是否停滞；合法长任务使用任务自身阈值。必要取消用官方取消工具，取消后仍需证明 queue/jobs/本地写入停止。

该机制只在 Codex 当前任务运行期间工作。电脑休眠、断电或应用关闭后，下次启动按 checkpoint 恢复；未来唤醒和定时监控仅在使用者另行要求时设置。
