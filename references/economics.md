# 成本与人工干预：任务路由原则

目标是让使用者以较低成本持续得到 Astra 主导的可靠交付，同时少做调度、传话和救场。Astra 保留规划、关键取舍和验收；低价模型承担已明确规格的实现、自测与定向修复。总 token 增多仍可能更便宜，减少 Astra 的有效判断也不算成功。

## 委派前判断

一次任务用一份短契约，避免把可共同验收的实现切成许多反复调用 Astra 的碎片。需求不清、核心设计未定时先由 Astra 解题；明确后委派。小改动、只需一次简单工具操作、外部依赖不可用时直接完成。用户不需要替模型分配子任务或手工粘贴不同模型的回复。

读现状、批量编辑、自测、修复可复现失败优先留在执行者上下文。Astra 检查实际改动和验证证据，必要时读完整文件；不要为审查而重新输出整份实现。审查默认返回「结论、定位、依据、修复验收条件」，让原执行者修复。重复出现同一失败或两轮定向修复仍未收敛时，保存状态、确认写入者空闲，再由 Codex 接管；这是止损阈值，不是允许跳过严重问题。

总成本包括 Astra 规划、委派、观察、验收、修复/接管的消耗，以及 DSH 调用和依赖维护。按输入、缓存、输出和实际价格分别记账；输出中的推理 token 不重复相加。API 等价价格可用于成本结构分析，但不能充当订阅实际额度扣减。没有额度数据时标记不可得。

## 减少不必要的人工介入

已有授权内的诊断、启动已允许恢复的 Host、查询原任务、复跑测试、定向修复和安全降级由 Codex 负责，无需使用者逐步批准。状态不变不反复提示，不让用户处理内部轮询。发生异常先按 reliability.md 有界恢复并保存 checkpoint，再决定是否有用户必须完成的动作。

需要人时只提出当前真正阻塞的一件事或一组相关事项：如补充不可推断的需求、本人填写 key、真实权限审批、确认 Claude 网络资格、超出原授权的外部操作。说明具体入口与下一步。未回答 Claude 网络问题不阻塞 Codex/DSH；缺 key 时给配置引导，并继续可完成的 Codex 路径。不得以减少干预为由自动代答审批、跳过验收、杀未知进程或更改账号规则。

## 每次交付最小记录

沿用原 taskId/checkpoint，记录路由原因、实际执行者、各阶段状态、验证结果、修复/降级与未完成项。评估收益时另记：

- 所有模型阶段的用量与可取得的费用；主控统计缺失写 null，不能写 0。
- 实际用户介入事件：时间、原因、要求用户做什么、是否阻塞、结果；操作分钟数只有实际测量才填。
- 自动处理事件：检测到什么、使用哪个既有授权、动作及结果。自动恢复次数不等于节省的人工次数。
- 冷启动安装、key 配置与维护单列；多次任务摊销必须说明任务数。

同等通过标准下，同时考察每次合格交付成本、用户介入次数、阻塞时间和完成耗时。原生 Codex 本身也能自主执行与恢复；比较 skill 增量须允许基线使用正常工具能力。不要把故障夹具的测试通过率包装为真实人工减少率。

## 套餐倍数的验证条件

若单次合格交付 Astra 资源占比为 r，在相同额度、同等质量且其它瓶颈不变的假设下，容量倍率约为 1/r。5、10、20 倍分别要求净减少 80%、90%、95%；规划、验收、修复和主控协调全部计入 r。实际月支出还要加 DSH，服务限速与耗时也可能限制吞吐。

2026-09-08 的官方页面列出 Plus $20、Pro $100（5 倍 Plus 用量）和 $200（20 倍）；价格比不能直接当额度比。当前实验不证明 $20 等于 $100/$200 或一个账号顶十个账号。项目不增加套餐额度；目标是在不改变账号规则的前提下，用合理分工减少每次交付所需的昂贵模型工作。
