# DSH 主控 + 按需专家：技术筛选协议

2026-09-09。目标是探索合格交付接近强模型、任务运行成本接近十分之一的可行路径。
不预设 skill 是最终形态，不预设顾问一定有增量。

## 本轮范围

首轮三个工程组件任务：现有增量摘要模块的改造、新用量账本、新费用预留状态机。
第一题取自真实仓库 5e4bc6e；后两题来自本原型的实际产品需要。它们是明确规格的小规模
工程实验，不是完整真实应用的端到端交付样本，也不是代表所有任务的随机抽样。

三条路径为正常 Codex/Astra、DSH 独立执行、相同 DSH + 可选 Astra 顾问工具。
Astra 保留正常文件、shell、测试能力，使用官方 CLI 的 workspace-write/自动审批审查；
没有 bypass policy，未沿用旧无工具生成基线。DSH 保留 standard 工具与原生子代理能力。
顾问的职责不同：提示要求只根据给定证据推理、不调用工具，实际出现工具调用则标为
协议违规，而不是宣称 read-only 沙箱能从机制上禁用所有读取工具。

每个尝试使用相同起点的独立目录。用户任务原文、初始源码和私有验收在首次模型运行前
保存哈希；可见测试双方相同。DSH 自己决定是否咨询、问题内容、证据和是否采纳。
父程序只转发，不替模型修订问题、选择代码或加入隐藏测试失败提示。

## 成本与质量

- 记录全部模型尝试和实际费用能取得的部分。报告值为冻结价格的 API 等价估算，
  不冒充订阅扣减、实际发票或“20 美元等于 200 美元”的实测结论。
- DSH 用量复用安装版官方 tokenUsage v2 和逐 turn 计量函数。chunk/final 按 attempt
  替换，失败重试另计；递归汇总实际后代，顾问用独立 CLI 账本。自动标题关闭。
- 模型路由来自 DSH 官方用量中的 route；Astra 请求型号明确，CLI 未提供实际路由时
  标为 requested。工具事件和模型自述分开，模型说完成不代表验收通过。
- CLI 只能提供 turn 聚合用量；涉及长上下文分档无法确定时，不发布精确完整费用。
  失败时没有原生 usage 的记录保留未知。压缩等辅助调用若未能核对，也不能补零。
- 原型开发、选题、父级研究、基准创建成本单列为研发，当前未精确归因，不称免费。
  每任务运行由确定性程序驱动；不需要父级 Astra 轮询、判断、修复或验收。
- 外部验收是固定脚本；所有尝试均保留，未通过不静默重跑。报告整任务通过数、
  功能断言及代码范围、耗时、费用、咨询次数与协议状态。
- API 正常缓存真实保留，单次样本不能排除顺序与服务负载效应；不把缓存优势全归功于路由。

每个任务最多 10 分钟、两次专家咨询。停止阈值在下一次调用前检查，不是能撤回
在途消费的硬账单上限。累计实验达到 STATE.md 的预算阈值则不再扩大。

## 修订与披露

摘要题最初的隐藏断言要求无错误时显式返回 failureSeen=false，但需求仅要求有错误时
返回 true。Astra 的初次验收 5/6，检查发现是断言越界。已在两条 DSH 路径开始前修订，
保留旧断言和初次结果；没有重跑模型或改 Astra 产物。预算题的零金额预留语义也在
该题任何模型运行前澄清，并对三条路径同步。哈希与修订时间随结果公开。

基础接入在首轮运行期间修复了计量、隔离与进程清理问题，因此这是带版本记录的
工程探索，不是已经冻结全部基础设施的正式确认实验。最终产品结论需要独立留出任务。

## 决策

三题仅用于筛查。没有咨询不算顾问失败，但也不能证明专家增量。若 DSH 单独已能完成，
应优先优化便宜路径的费用与耗时。若顾问组修复单独路径的缺口，再分析是自主求助、
事后诊断帮助还是额外信息造成；三者不得混记。90/10 是目标，不是任何一项局部指标。
